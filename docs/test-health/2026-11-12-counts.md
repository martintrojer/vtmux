## The macOS minimum

The README says macOS 15 or later: the oldest macOS that runs vtmux's tests (CI's and the release's `macos-15` runners). What the binary declares is lower:

- `otool -l vtmux | grep minos` on the 3.8-beta3 release binary (`vtmux-v3.8-beta3-aarch64-apple-darwin.tar.gz`): `minos 11.0`, Rust's default for `aarch64-apple-darwin`.
- `otool -l libghostty-vt.a | grep minos` on a local build of the pinned libghostty-vt (Zig 0.17.0, native target): `minos 13.0` in all 12 objects. `build.rs` passes no `-Dtarget` on a native build, so Zig uses its own default.
- No macOS older than 15 has run it, so 13 and 14 are not claimed.

## mise

The README's install and upgrade lines, checked with mise 2026.11.6 in a private config (`MISE_GLOBAL_CONFIG_FILE`, `MISE_DATA_DIR`, `MISE_CACHE_DIR`, `MISE_STATE_DIR` under `~/.cache/pf-docs-mise`), with `github:martintrojer/vtmux` installed at 3.8-beta2 and `MISE_MINIMUM_RELEASE_AGE=0` (mise hides a release younger than its minimum release age, and beta3 was under a day old):

- `mise upgrade --dry-run vtmux`: no output, exit 0. mise doesn't match the short name.
- `mise upgrade --dry-run github:martintrojer/vtmux`: `Would install github:martintrojer/vtmux@3.8-beta3`, and 3.8-beta2 scheduled for pruning after 24h. The real run upgraded it.
- A link to `$(mise which vtmux)` made before the upgrade still ran 3.8-beta2 after it; `ln -sf "$(mise which vtmux)" <link>` after it points at 3.8-beta3, and the link named `tmux` prints `tmux 3.8`.
- A link named `tmux` to mise's shim (`shims/vtmux`) doesn't run vtmux: mise picks the tool by the name it was run as. With `PATH=/usr/bin:/bin` it fails (`tmux is not a valid shim`); with another `tmux` on `PATH`, it runs that one.

## The replay at these counts
