# Reading a long history in order, 2026-11-08

Task `perf_search_1m`. Host: the Linux server of *Method* (Linux 6.16, AMD EPYC Genoa, 96 cpus), shared with other agents' gates; load 16-22 throughout. Release builds of vtmux; tmux 3.8 from `cargo xtask ref-tmux`. `base` is main `0107471` (`/tmp/w129/vtmux-base`), `after` the branch at `5b55ed2` (`/tmp/w129/vtmux-after`).

Commits: `4bc01ac` (Ghostty patch 0033, `ghostty_grid_ref_down` / `_up`), `5b55ed2` (vt: read rows in order by stepping from the last one).

## The cause

Every row read resolved its row with `ghostty_terminal_grid_ref`, which walks Ghostty's page list from the oldest page (`PageList.pin` -> `getTopLeft(.screen).down(y)`). One row is O(pages), so a reader of all `n` rows is O(n * pages), quadratic in the history. Readers of all rows: copy-mode search (`ScreenCopy::ascii_text`, `used_row`), copy mode's reflow, `capture-pane -S -` (any flags), `capture-pane -M`, `capture-pane -R`, `#{history_bytes}` / `#{history_all_bytes}`, the alternate screen coming up (it copies the primary history, which tmux goes on showing: `freeze_history`), and view mode's re-read (`Grid::extend_from`).

Now `row_ref_near` steps from the row read before with patch 0033 (`Pin.down` / `Pin.up`) whenever that crosses no more rows than the lookup would. Copy mode's entry copy keeps its last row for its lifetime (its terminal never changes); readers of the live pane keep it for one pass, under a borrow of the pane.

Jumps (`history-top`, `goto-line`) were never quadratic: a redraw reads one screen of rows, a walk each before, a walk and steps now; 2-3 ms either way at 1M lines with a client attached, as tmux.

## What is left

`perf record -g` of the after server while the alternate screen came up over 1M lines: 59% in `read_cells` and most of the rest in page faults under `malloc` and `read_cells`. Each row is turned into a `Vec<RowCell>` of 120 cells (text, style, link target), and the frozen copy keeps them. tmux saves only the visible rows (`screen_alternate_on`, screen.c:700-721) and goes on reading the history from its own grid. vtmux copies the history because Ghostty can read only the active screen; avoiding the copy needs a way to read the primary screen's pages while the alternate screen is up. Not done here.

The captures pay the same per-row, per-cell construction (`read_cells`, `emit_row`), and `-M` also keeps every row it reads in the copy. A plain capture of a narrow ASCII row could go through the row's text as the search does. Not done here.
