# ghostty_vt1_rebase: Ghostty commit 3bd54e025 to the libghostty-vt 1.0.1 release

The sys crate builds the libghostty-vt 1.0.1 release (tag `vt-1.0.1`) from its two release tarballs, checked by SHA-256, with `zig build --system` on the unpacked Zig packages. Zig fetches nothing. The 42 patches were rebased one by one. Two are dropped because 1.0.1 has them (0001 keep-one-free-page-resident, 0018 reflow-hyperlink-map-full), and 40 stay, not squashed. `third_party/libghostty-rs/VENDOR.md`, *libghostty-vt 1.0.1*, says what changed in each patch and why it stays.

## Found by the existing tests during the rebase

- `persist::tests::a_full_checkpoint_carries_every_pane_s_terminal`: importing a page in vtmux rows failed with `GHOSTTY_INVALID_VALUE` when the page had many links. 1.0.1 sizes the hyperlink map on its own (`Capacity.hyperlink_cells`), and patch 0017 did not size it. Fixed in 0017.
- `snapshot_term::long_history_in_both_forms`: a row lost `GRID_LINE_EXTENDED`. 1.0's new `printSliceMixed` fast path keeps none of tmux's row bookkeeping (it also sizes by Ghostty's table, not vtmux's width overrides). vtmux no longer takes that path (patch 0013).
- `term::tests::page_rows_matches_ghostty`, `history_budget_steps_by_page`: the standard page is now 397 312 bytes (was 401 408) with 25 712 bytes of metadata (was 26 128). A probe of every width from 1 to 700 columns, plus 800 to 20 000, fits only 371 600 to 371 607 grid bytes. The constants in `term.rs` are updated; the aarch64 macOS page is 409 600 bytes, unchanged by the rounding, but CI checks it.
- Ghostty's own `printSlice` differential and hyperlink tests: patch 0037's kept last cell also had to go into 1.0's two new wide-at-edge fast paths.
- The wrapper's tests: the `GhosttyClipboardWrite` and `GhosttyClipboardRead` records lost their `size` field, `GRAPHEMES_BUF` now takes a `GhosttyCodepointBuffer`, and the OSC title is a `GhosttyString`.

## Review round

The opus review found one MEDIUM. 1.0.1's `ghostty_key_event_set_utf8` takes a `GhosttyString` by value, and `bindings.rs` declared a pointer and a length. The two pass in the same registers on x86-64 and aarch64, so keys worked, but the declaration was wrong. It also found two lows: seven output buffers declared `char *` where C has `uint8_t *`, and a build that fetched the second tarball when only one of `GHOSTTY_SOURCE_TARBALL`/`GHOSTTY_DEPS_TARBALL` was set. All three are fixed. A new test, `libghostty-vt/tests/abi.rs` (1,082 checks compiled by `zig cc` against the installed headers: functions, callback types, struct fields, layouts), fails on the old bindings with 8 `conflicting types` and passes now. The orchestrator ran the oracle replay, `--upgrade-every 3` and attach on aarch64 macOS at 95ab305d: all green, so the macOS page constants hold.
